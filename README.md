# MAX Chat — чат для мессенджера MAX на GREEN-API

Тестовое задание на должность «Фронтенд разработчик React».

Веб-интерфейс для отправки и получения текстовых сообщений в мессенджере **MAX** через сервис [GREEN-API](https://green-api.com/max). Внешний вид повторяет [web.max.ru](https://web.max.ru/): левая панель, список «Чаты» с поиском и кнопкой «+», окно переписки с «пузырями» сообщений. Тёмная тема как в MAX, светлая включается по системной настройке.

## Возможности

- Вход по `idInstance` и `apiTokenInstance` из личного кабинета GREEN-API (`apiUrl` подставляется автоматически, можно изменить). Учётные данные проверяются методом `getStateInstance`.
- Создание чата по номеру телефона получателя: номер нормализуется (`8 999…` → `7999…`), а числовой `chatId` MAX определяется методом `checkAccount`.
- Отправка текстовых сообщений методом [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/): оптимистичное отображение, статусы (отправляется / отправлено / прочитано / ошибка).
- Получение сообщений через [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/): цикл `ReceiveNotification` (long polling, 20 с) → обработка → `DeleteNotification`.
- Ответы собеседника появляются в нужном чате; сообщения от новых собеседников создают новый чат.
- Непрочитанные, поиск по чатам, разделители дней, сохранение переписки в `localStorage`.
- Предупреждение, если в настройках инстанса задан `webhookUrl` или выключены входящие уведомления.
- Адаптивная вёрстка: на телефоне список и чат открываются как отдельные экраны.

## Стек

React 19, TypeScript, Vite. Без UI-библиотек и менеджеров состояния: состояние чатов — `useReducer` с чистым редьюсером, покрытым тестами (Vitest).

## Локальный запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
git clone <ссылка на репозиторий>
cd max-chat
npm install
npm run dev
```

Откройте http://localhost:5173 и введите данные инстанса.

### Подготовка инстанса GREEN-API

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com), создайте инстанс MAX и авторизуйте его по QR-коду (в приложении MAX: Профиль → Устройства → Войти по QR-коду).
2. Скопируйте `idInstance`, `apiTokenInstance` и `apiUrl`.
3. В настройках инстанса:
   - поле **URL для отправки уведомлений (webhookUrl) должно быть пустым** — иначе HTTP API не отдаёт уведомления;
   - включите «Получать уведомления о входящих сообщениях и файлах»;
   - по желанию включите уведомления о сообщениях, отправленных через API и с телефона, и о статусах сообщений — тогда в чате появятся галочки «прочитано» и сообщения, отправленные с телефона.

### Запуск без реального инстанса (мок API)

В репозитории есть мок GREEN-API — удобно, чтобы посмотреть интерфейс без регистрации:

```bash
npm run mock   # http://localhost:3001
npm run dev
```

В форме входа укажите `apiUrl` = `http://localhost:3001`, любой числовой `idInstance` и любой токен. На каждое сообщение «собеседник» ответит через 2 секунды.

## Деплой

Сборка статическая (`dist/`), с относительными путями — подходит любой статический хостинг. В репозитории настроен GitHub Actions workflow `.github/workflows/deploy.yml`: при пуше в `main` запускаются тесты, сборка и публикация на GitHub Pages (в настройках репозитория: Settings → Pages → Source: GitHub Actions).

GREEN-API разрешает запросы из браузера (CORS), поэтому бэкенд или прокси не нужны.

## Структура

```
src/
  api/            клиент GREEN-API и типы уведомлений
  chat/           модель чатов: разбор уведомлений, редьюсер, тесты
  hooks/          цикл получения уведомлений (long polling)
  components/     экран входа, список чатов, окно чата, диалог нового чата
  lib/            форматирование, хранение в localStorage
scripts/
  mock-green-api.mjs   мок API для локальной разработки
```

## Замечания

- Учётные данные хранятся в `localStorage` браузера, чтобы не вводить их после перезагрузки; кнопка «Выйти» их удаляет.
- Приложение одновременно забирает уведомления из очереди инстанса, поэтому не стоит параллельно запускать другой потребитель того же инстанса (бот, вторую вкладку) — уведомления разойдутся между ними.
- Нетекстовые входящие сообщения (фото, стикеры и т.п.) показываются заглушкой: по заданию поддерживаются только текстовые.
